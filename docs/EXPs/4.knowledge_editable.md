## Post-edit Answer Consistency

新的口径改成“固定 round-0 baseline 的全局精度分解”：
先统计 `round-0` 的全局 Accuracy，记为基准 `acc0`。之后每一轮都把当前轮 Accuracy 与 `acc0` 对比。若当前轮精度不低于 `acc0`，则记 `new-answer correct ratio = 100%`；若下降，则记 `new-answer correct ratio = acc_curr / acc0`，并把剩余的 `(acc0 - acc_curr) / acc0` 拆成两部分：`old-answer leakage ratio` 和 `other error ratio`。其中 `old-answer leakage` 定义为模型输出命中当前轮之前任一历史答案。

## Update Amplification
统计知识更新的开销，按照数据集分类。
一篇文档中的某个知识发生了更新，对于DAG-KV来说，更新后的文档提取成多个三元组，然后去图索引中查找，并如果图索引中存在那么就不需要更新，否则就计算三元组对应的KV Token，然后更新图索引。由于DAG-KV会将一个三元组转换成2个 KV Token，因此DAG-KV的知识更新开销是 2 token / update knowledge. 
对比项有两种:
  MSA: document-level reuse，如果一篇文档中的某个知识发生了更新，他们就需要重新计算整篇文档，因此知识更新开销是 total tokens this doc / update knowledge.
  Cacheblend：chunk-level reuse, 文档先切块，然后chunk-wise匹配，如果命中就不需要重新计算。但是需要考虑如果更新的内容导致Token数量改变，那么后续的chunk就会发生偏移，此时就必须重算。


已在 collect_update_amp.py (line 1) 实现你要的两个功能：
统计输入数据集的平均文档 token 数。
对每个样本先 tokenization，再随机选择一个位置，随机执行 replace 或 insert，最后按可配置的 --chunk-size 统计需要重算的 token 数。
实现口径是“样本级文档”：
优先把 context 展平成一段文本来算 token。
对 CacheBlend 的重算量，按编辑后文档切 chunk，凡是和原来同位置 chunk 不一致的块，都把该块 token 计入 recomputed_tokens。
replace 一般只影响局部 chunk，insert 会自然反映后续 chunk 偏移带来的重算。
